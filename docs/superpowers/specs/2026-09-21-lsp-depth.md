## Binding rulings

These lock underspecification. The implementation plan may only add detail, not contradict.

### Surface

1. **Same tool.** Extend `LspOperation` / `LspInput.operation` enum only. Description string updates in place. Pairing unchanged.

2. **New operations (same `{ path, line, character? }` shape).**

   | `operation` | Method | Why |
   |---|---|---|
   | `implementation` | `textDocument/implementation` | Definition on an interface/trait lands on the type, not the impl. |
   | `typeDefinition` | `textDocument/typeDefinition` | Agents need a **location** to `Read`; hover markdown is already clipped at 8k. |
   | `diagnostic` | Pull `textDocument/diagnostic` if `diagnosticProvider`; else drain buffered `publishDiagnostics` for that URI | Type-check hole. Lint sidecar skips `.ts/.tsx`. File-scoped, on-demand, capped. |

   `line` stays required in the schema (0-based). Diagnostic **ignores** line/character. Do not fork parse. Do not add properties (`scope`, `includeWarnings`, `format`) this door.

3. **`isEnabled` stays file-gated.** Tool hidden until `<projectCwd>/.ravenclaw/lsp.json` parses to at least one server. No env flag, no “detect typescript-language-server on PATH.” `packages/cli/src/exec.test.ts` hide-without-file test stays green.

4. **`lsp.json` additive, fail-open parse:**

   ```json
   { "servers": [{ "command": "…", "args": [], "extensions": [".ts"], "initializationOptions": {} }] }
   ```

   `initializationOptions?: unknown` passed through to `initialize`. No per-server operation allowlist (the tool enum is the allowlist). No `env` (secrets). No `rootUri` override. First matching extension still wins. One process per `(workspaceCwd, command, args)`.

5. **SDK still omits LSP.** Children stay without LSP. Do not add `LSP` to `general` / `file-finder`.

### Handshake honesty

6. **Store `ServerCapabilities`.** If a provider is explicitly `false`, return `LSP failed: server does not support {operation}` (fail-open string, no method sent). If absent, still try.

7. **Advertise** client capabilities for the six ops plus `publishDiagnostics` / `diagnostic`, and `workspace.workspaceFolders.supported`. Send `workspaceFolders` and `processId: process.pid`.

8. **Reverse-RPC this door:**

   | Server request | Reply |
   |---|---|
   | `workspace/workspaceFolders` | the folders we advertised |
   | `workspace/configuration` | `[{}]` per item |
   | `window/workDoneProgress/create` | `null` (already) |
   | `workspace/applyEdit` | `{ applied: false }` — tool is read-only |

9. **Buffer last `publishDiagnostics` per URI**, max 20 items. Incoming JSON-RPC frames &gt; 256 KiB are dropped (do not `JSON.parse` a diagnostic novel). **Cap in the LSP client only** (`packages/core/src/lsp/client.ts` `onData`, or an optional max argument used solely by LSP). Do **not** change shared `consumeJsonRpcFrames` in `packages/core/src/mcp/client.ts` — MCP uses that parser.

10. **Best-effort `shutdown` + `exit` then `kill` on drop.** Fail-open if that hangs. Do not wait on the query timer for shutdown.

11. **Timeouts.** Initialize **30s**; query **8s**; diagnostic drain wait ≤ **1.5s** (drain is the query, not stacked as a second full wait). Distinct messages: `LSP failed: timed out` vs `LSP failed: language server not available`.

12. **Workspace root vs config root.** `loadLspConfig` from `projectCwd ?? cwd`. Spawn / `rootUri` / `workspaceFolders` / file jail from **`turn.cwd`**. After `EnterWorktree`, the server indexes the worktree. Session key includes that cwd.

13. **Host-only.** LSP spawn and file reads stay host `node:fs`. Do not docker-exec the language server. Do not route through WorkspaceFs docker backend.

14. **Read-only + leftover-allow stays.** `implementation` / `typeDefinition` / `diagnostic` remain `isReadOnly` / `isConcurrencySafe` / `interruptBehavior: 'block'` / `checkPermissions` allow.

15. **Result cap stays 8_000** on every op. Diagnostic additionally: compact lines `path:line:col severity code message`, **max 20**, errors before warnings, then the 8k clip. Position ops stay pretty-printed JSON + clip.

16. **Fail-open vs fail-closed.**

    - Fail-open (string, turn continues): missing server, spawn ENOENT, crash, timeout, unsupported capability, RPC error, unreadable path.
    - Fail-closed (refuse): `workspace/applyEdit` (`applied: false`); `isEnabled` false when config missing; path outside workspace jail.
    - Never fail the session because a language server died. Next query may restart.

17. **Do not replace the lint sidecar** and do not auto-append diagnostics onto Write/Edit.
