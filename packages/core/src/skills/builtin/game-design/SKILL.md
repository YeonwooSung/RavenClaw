# game-design

Load this before writing game code. The skill index cannot carry every trigger, so the body does. Use it for 게임 기획, a GDD, a core loop, pillars, "what game should we make", scoping a jam game, and any request that arrives before implementation.

Write one page, then stop. Do not implement until the user accepts that page.

The page has these eight fields:

1. fantasy — one sentence
2. player verb — one verb
3. core loop
4. pillars — exactly three
5. scope box — in / out
6. session length
7. one riskiest assumption
8. one playtest question

After the user accepts the page, open Skill name `gamedev` and only the catalog skills that cover the accepted slice: path `catalog/<name>/SKILL.md`. Implement that slice only.

Do not widen the scope box during implementation. If the user asks to widen it, rewrite the page and wait for acceptance again. This is a writing rule, not a permission gate or a new tool.

Do not teach level layout, pacing, hit-stop, or juice here. When the accepted slice needs those, open only the path:

- `catalog/level-design/SKILL.md`
- `catalog/game-feel/SKILL.md`
- `catalog/game-jam/SKILL.md`
- `catalog/prototype-fast/SKILL.md`
